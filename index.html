01文件可试搭

多店晨检：今天先处理哪三件事

“每天开工先告诉我最该处理的三件事，不要把所有报表再抄一遍。”

展开应用与改进路径 ＋

适用经营情境：淘宝天猫 / 拼多多 / 抖店 / 微信小店。不是平台已接通标识。

遇到什么事

一个人管几家店，早上轮流打开订单、客服和库存页面，看到很多数字，却不知道先找谁。

先准备什么

各店待办/订单/咨询摘要、昨天未结问题、负责人表；无连接时由商家导出脱敏文件。

昭回怎么发现

每天开工前用 Timer 读取新增文件及上轮状态，先核对店铺覆盖和导出时间，再按商家确认的紧急程度排序。

先替你做到哪一步

产出三件优先事项、证据、建议负责人和下一步；其它事项归档但不丢弃，同一问题沿用原编号。

你会拿到什么

示例：先核实今日到期订单，其次补齐主推款规格，最后跟进已签收的换货件；有一家店未同步，单独说明。

下一轮怎么改进

商家记录采纳、误报、已经处理或优先级不对；每周提出排序调整，用旧问题回放后再确认采用。

什么时候交给人

人决定任务归属和对外动作；本地清单不是已经在飞书/ERP里建了工单。

怎样判断有用

采纳项/已审阅项、遗漏紧急事项数、重复待办数；没有完整数据就不评价全店。

02文件可试搭

主推商品突然没人问：先排查再下结论

“这款以前每天有人问，最近安静了，帮我找先查什么。”

展开应用与改进路径 ＋

适用经营情境：淘宝天猫 / 抖店 / 拼多多 / 小红书。不是平台已接通标识。

遇到什么事

商品咨询变少，运营想立刻改标题或降价，但可能只是规格断货、链接状态变化或报表口径不同。

先准备什么

同一商品的分日曝光/访问/咨询摘要、可售规格、活动日历和历史修改记录；只用当前账号可提供的数据。

昭回怎么发现

每日对比相同时间窗和渠道，先看数据完整性，再看访问、咨询与商品状态在哪一层变化。

先替你做到哪一步

形成排查顺序及每项证据：数据缺失→不可售→流量变化→内容匹配；将可能原因与已证实原因分开。

你会拿到什么

示例：咨询下降与M码缺货同时出现；建议先恢复规格信息核查，不把它直接说成平台限流。

下一轮怎么改进

记录人工最后确认的原因，积累本店常见排查路径；下一次优先查已高频发生的问题，但保留反例。

什么时候交给人

不猜平台算法，不自动改价、改标题或购买流量；样本不足就继续观察。

怎样判断有用

排查耗时、原因核实率、无证据归因次数。

03需核验新鲜读取

销量或咨询归零：其实可能是数据断了

“店铺数据突然变零时，先判断是生意出问题，还是你没读到。”

展开应用与改进路径 ＋

适用经营情境：淘宝天猫 / 拼多多 / 抖店 / 京东。不是平台已接通标识。

遇到什么事

昨天有业务，今天报表全零；若AI立即下结论停掉主推，会把采集故障当经营失败。

先准备什么

最近成功读取时间、当前读取回执、结果覆盖、已知业务样本；须有可验证的只读连接，或及时补交导出文件。

昭回怎么发现

按商家设定的检查窗口核对最后成功读取及已知样本；当前连接只支持什么就检查什么，不假设有全平台健康接口。

先替你做到哪一步

将结论标记为数据待确认，保留最后可信快照的时间，输出补数据清单，停止基于零值生成经营调整建议。

你会拿到什么

示例：不是确认今天零单，而是今天的订单来源未更新；需要重新授权或重新导出。

下一轮怎么改进

记录真实停业、真实零业务和读取中断三类结果，提出更合适的异常判别条件。

什么时候交给人

商家恢复授权；无法取得健康数据时不绕登录，不用旧数据冒充实时数据。

怎样判断有用

把采集失败误报成经营下滑的次数、恢复后可核对的覆盖率。

04文件可试搭

上新或大促倒计时：缺哪份材料

“离活动还有几天，替我每天检查哪些准备还没完成。”

展开应用与改进路径 ＋

适用经营情境：淘宝天猫 / 抖店 / 京东 / 小红书。不是平台已接通标识。

遇到什么事

商品图已做完，但规格表、赠品说明或仓库确认还没到；群里说过不等于交付完成。

先准备什么

商家提供的活动时间、提交要求、商品清单、负责人及资料目录；截止时间以本次活动官方页面为准。

昭回怎么发现

通过文件更新或每日 Timer 比对清单，识别缺文件、旧版本、负责人未确认和活动范围不一致。

先替你做到哪一步

生成缺口清单与资料请求草稿，说明是哪件商品缺什么、影响哪个截止点，不自动提交报名。

你会拿到什么

示例：3款中有1款缺新版规格，赠品范围尚未确认；已有海报不能当作报名全部完成。

下一轮怎么改进

记录每次临时补救的原因，把真正影响交付的检查项加入下一次活动清单候选，删去无用项需确认。

什么时候交给人

品牌资质和活动提交由负责人核验；不会因为材料长得像就认定合格。

怎样判断有用

准备遗漏数、截止前返工次数、材料版本错误数。

“下班前帮我把没解决的咨询说清楚，让下一班能直接接手。”

遇到什么事

白班承诺查仓库，晚班只看到一句催促；买家重复解释，客服又重复要凭证。

先准备什么

授权范围内的脱敏会话摘要、未结工单、已经确认的承诺与下一班负责人。

昭回怎么发现

你会拿到什么

示例：客户已提供缺件照片，仓库尚未核实；接班后先追仓库，不再让客户重新拍摄。

什么时候交给人

默认文件交接，不代表已监听所有平台聊天；接管和发送仍通过现有受控路径。

怎样判断有用

重复索要材料次数、交接后追问次数、同一问题重复建档数。

06文件可试搭

周复盘：上周说要改的事改了吗

“每周别只写总结，追踪上周决定的改进有没有真正落地。”

展开应用与改进路径 ＋

适用经营情境：淘宝天猫 / 拼多多 / 抖店 / 小红书 / 京东 / 快手 / 微信小店。不是平台已接通标识。

遇到什么事

会议每周都说要补尺码说明、减少催单，却没有人回看是否完成以及问题是否再发生。

先准备什么

上周行动清单、负责人反馈、相关新版资料和本周同类问题记录。

昭回怎么发现

固定周复盘读取同一工作区状态，核对任务是否有完成证据、是否仍有同类问题，而不是只看勾选完成。

先替你做到哪一步

输出已完成且有效、完成但未见效果、未完成、证据不足四组清单，延续原任务编号。

你会拿到什么

示例：详情页已改，但同类尺码咨询未减少；先核对新版是否真正上线以及样本量。

下一轮怎么改进

把有效做法整理成待批准的店铺经验；无效做法保留失败原因，不在下周继续复制同一建议。

什么时候交给人

负责人确认有效性；不能把相关性当因果，也不能自动关闭有争议的任务。

怎样判断有用

有结果证据的改进项/已完成项、重复问题率及样本窗口。

同款多渠道：参数和承诺不一致

“帮我看看同款在几家店的说法有没有打架，哪些差异是故意的也要分清。”

遇到什么事

天猫写新包装，拼多多还是旧规格；不同渠道赠品本来不同，却被系统误判成错误。

先准备什么

已确认的跨渠道商品映射、各店商品快照、渠道专属权益和正式商品主资料。

昭回怎么发现

按文件更新或每日检查对比同一对象的材质、数量、尺寸、版本与承诺；先区分公共事实和渠道规则。

先替你做到哪一步

你会拿到什么

示例：规格容量冲突需核实；赠品不同是已批准渠道差异，不应强行统一。

下一轮怎么改进

把商家确认的差异记为有范围、有期限的例外候选；定期复核，避免例外永久掩盖错误。

什么时候交给人

渠道差异和权威字段来源由商家确认；单个店铺的新描述不能自动改全渠道。

怎样判断有用

有效冲突率、误报渠道差异数、修正后再次发生的字段错误。

怎样判断有用

错绑拦截数、歧义未解决数、已审样本中的身份准确率。
